МИСИЯ 404 — КАЧВАНЕ В RENDER (БЕЗПЛАТЕН ВАРИАНТ)

ПРЕДИ ПУБЛИКУВАНЕ:
- Прегледайте кода/тествайте играта. Не въвеждайте лични данни на ученици.
- Не включвайте game_data.json, teacher_config.json, .env в GitHub! Вече са в .gitignore.
- Дори да публикувате от публичен GitHub repository, никога не качвайте учителския ключ в него.

СТЪПКИ (Render Blueprint):
1. Направете НОВО празно GitHub хранилище и качете всички файлове от тази папка в корена му.
2. В Render изберете New > Blueprint и посочете GitHub хранилището.
3. Render ще прочете render.yaml; потвърдете само БЕЗПЛАТНИТЕ free ресурси:
   - Python Web Service (Frankfurt),
   - PostgreSQL (Frankfurt, free).
4. Изчакайте deploy да стане Live, след това отворете генерирания HTTPS адрес.
5. За да намерите кода за учителя: в Render Web Service > Environment,
   вижте MISSION404_TEACHER_KEY. Не го споделяйте с ученици.
6. Учителят отваря HTTPS-адреса + /teacher, въвежда своя код и създава сесия.
7. Дайте директния HTTPS линк /join?code=... на учениците.
8. Преди часа пуснете пробна игра с два браузъра/компютъра.

ВАЖНО: Render FREE ограничения (проверете актуалните условия):
- При липса на заявки ~15 минути уебсървърът може да заспи; първата заявка след това
  може да отнеме около минута. Отворете играта 10 минути преди часа.
- Безплатната PostgreSQL база изтича след 30 дни, затова я създайте близо до учебния час.
- Render може да направи рестарт или техническа поддръжка; проверете играта предварително.
- Базата няма автоматични резервни копия на безплатен план.
- Не правете повече от една Python работна инстанция: данните се синхронизират
  с глобална ключалка в един сървърен процес и се съхраняват в PostgreSQL.
- Ако ще използвате играта редовно за много класове, архитектурата има нужда от
  по-добро удостоверяване, ограничаване на заявките и нормализирана база данни.

ЛОКАЛЕН РЕЖИМ:
Старият START_WINDOWS.bat остава работещ без база и без платени услуги.
